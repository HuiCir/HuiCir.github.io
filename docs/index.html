Token Never Sleeps 指令集与使用技巧

这份文档覆盖安装、初始化、编译、运行、监控、权限审批、恢复、FSM 模拟和 template case。默认假设你已经有 Node.js 22+，并且 `claude` CLI 在 PATH 中可用。

Package: token-never-sleeps Node.js 22+ tmux optional

Install

npm install -g token-never-sleeps
tns help

`tns` 是纯 TypeScript npm CLI。它保留本地 runner、状态追踪、executor/verifier workflow、tmux-aware startup、 plan import、artifact index 和 workspace templates。

Quick start

tns init --workspace ./my-task
cd ./my-task

tns compile --config ./tns_config.json
tns doctor --config ./tns_config.json
tns status --config ./tns_config.json
tns run --config ./tns_config.json --once

`init` 会写入 `task.md`、`tns_config.json` 和 `.tns/`。首次运行前建议先 `compile` 和 `doctor`： 前者生成可读的 orchestration program，后者检查配置、二进制、tmux 和 workspace preflight。

Common loop

# manual stepping
tns run --config ./tns_config.json --once

# long direct loop
tns run --config ./tns_config.json

# choose managed tmux when configured, otherwise direct
tns start --config ./tns_config.json

# read-only live snapshot during long runs
tns btw --config ./tns_config.json --events 12 --reviews 5

Command reference

tns init创建 workspace、task、config 和 `.tns/` 状态目录。
tns compile把 task/config 编译为 `.tns/compiled/program.json`。
tns simulate模拟配置或编译出的 FSM program，可用 `--set key=value` 注入上下文。
tns doctor执行配置、binary、tmux 和 preflight 诊断。
tns status读取并报告 sections、freeze、approvals、artifacts、locks、tmux 和 runtime。
tns btw只读快照，不获取 workspace lock，适合长任务观察。
tns run直接运行 TNS loop，`--once` 只推进一轮。
tns start按配置选择 managed tmux 或 direct runner。
tns run-tmux显式 tmux 模式；系统没有 tmux 时会 fail fast。
tns approve授予一个 named permission tag，让被冻结的高权限步骤继续。
tns revoke撤销已授予 tag，影响后续运行。
tns trace查看最近 activity events、validator outcomes 和 section 轨迹。
tns recover清理 stale runtime、stale locks 和 lingering in_progress sections。
tns plan-import把 markdown plan 导入 tracked sections。
tns freeze手动冻结 workspace。
tns unfreeze解除 freeze 状态。

Templates

tns init --workspace ./novel-project --template novel-writing
tns init --workspace ./fsm-case --template fsm-control-flow

npm 包内置 `blank`、`novel-writing`、`fsm-control-flow`。archive 里还有一个完整的 `audiobook-video` 实机 template， 展示如何用 section、approval tag、command bridge 和 validator 管住外部媒体生成与 ffmpeg 剪辑。

Compile and synthesis

tns compile --config ./tns_config.json
tns compile --config ./tns_config.json --synthesize
tns compile --config ./tns_config.json --synthesize --apply

`compile` 的输出让 executor/verifier 不再临场猜测任务结构。`--synthesize` 会调用 compiler agent 生成 preflight、 permissions、validators、command hooks、policy 和 externals 的结构化 patch；`--apply` 把 patch 合回 config 后重新编译。

Permissions

{
  "permissions": {
    "default_profile": "standard",
    "profiles": {
      "standard": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["pwd", "ls", "cat", "sed", "rg", "find", "git", "node"],
        "workspace_only": true
      },
      "media_render": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["node", "ffmpeg", "ffprobe"],
        "requires_approval": "media-render",
        "workspace_only": true
      }
    },
    "section_profiles": [
      { "match_title": "Deterministic edit and QA", "profile": "media_render" }
    ]
  }
}

缺少 required approval 时，TNS 会 freeze workspace 并写入 `.tns/approvals.json`。人工确认后运行： 

tns approve --config ./tns_config.json --tag media-render --note "operator reviewed"
tns run --config ./tns_config.json --once

Monitoring and recovery

tns btw --config ./tns_config.json
tns trace --config ./tns_config.json --limit 40
tns recover --config ./tns_config.json
tns recover --config ./tns_config.json --force

`btw` 是长任务最常用的只读观察面；`trace` 看事件轨迹；`recover` 用于清理 stale lock、runtime 与中断中的 section。 watchdog 由 `monitor.heartbeat_seconds`、`monitor.max_agent_runtime_seconds` 和 `monitor.kill_grace_seconds` 控制。

Practical tips

  • 先把 `task.md` 写成可验收 section，不要让一个 section 同时承担探索、实现和 QA。
  • 对外部工具步骤使用 approval tag；让 agent 先产出计划和 manifest，再放开生成或渲染权限。
  • 长任务运行中优先使用 `tns btw`，避免监控命令扰动 runner 锁。
  • 每次大幅改 task/config 后重新 `tns compile`，让 `.tns/compiled/program.json` 成为稳定 contract。
  • 把确定性检查写成 command hooks 或 validators，而不是让 verifier 只做自然语言判断。

Audiobook-video case

# archive template flow
node scripts/check_manifest.mjs
node scripts/check_manifest.mjs --assets
node scripts/build_video.mjs
node scripts/check_video.mjs

这个 case 的价值在于它不是“agent 写点文字”式 demo：它要求源章节、英文脚本、多 voice 资产、16:9 背景图、 BGM、ffmpeg 剪辑、字幕烧录和最终视频 QA 都可追踪。TNS 用 section 和 validator 把这条链路拆开，使失败可以定位到 manifest、 asset 或 render 阶段。
