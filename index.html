Design philosophy

长时 agent 不是更长的 prompt，而是更明确的 machine contract。

Agent-as-coprocessor Claude 处理一个 section，AVM 决定下一跳
File-system state bus 所有状态落在 `.tns/`，崩溃后仍能追踪
Defense in depth preflight、pre_step、post_step、post_run 分层验证
Crash-safe locks runner、workspace、state 通过命名锁协调

Core thesis

TNS 的核心不是替代 agent，而是把 agent 放进一个可治理的执行环境：任务边界、权限、验证、恢复、审计和 usage-limit 之后的接力，都不再依赖单个对话窗口还活着。

How AVM works

从自然语言任务到可模拟的有限状态程序。

01 Source

`task.md` 描述目标、section 和 acceptance criteria；`tns_config.json` 描述 workspace、权限、validator、hook。

02 Compile

`tns compile` 生成 `.tns/compiled/program.json`，把隐含流程变成 FSM、外部依赖和机器可读 contract。

03 Run

runtime 选择当前 section，调用 executor，再交给 verifier，并在每个阶段执行 validator 与 policy。

04 Recover

activity、reviews、handoff、locks、runtime heartbeat 都落盘；中断后可以 `tns recover` 或直接继续。

Quick start

安装 npm CLI，初始化一个可运行 workspace。

npm install -g token-never-sleeps

tns init --workspace ./my-task
cd ./my-task
tns compile --config ./tns_config.json
tns doctor --config ./tns_config.json
tns run --config ./tns_config.json --once
tns status --config ./tns_config.json

Operational mode

短任务用 `run --once` 手动步进；长任务用 `tns start`，配置 tmux 时进入 managed runner，否则走 direct mode。 运行中用 `tns btw` 做只读观察，不抢 workspace lock。

Real machine case
