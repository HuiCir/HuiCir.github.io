Let agents survive long tasks without relying on memory.

Token Never Sleeps compiles your task.md into an executable AVM contract, then an external runtime schedules the executor, verifier, permissions, watchdog, state files, and recovery paths. The model handles one bounded step; the real long-horizon control stays outside the agent.

Design philosophy

Long-horizon agents need explicit machine contracts, not longer prompts.

Agent-as-coprocessor Claude processes one section, AVM decides the next transition
File-system state bus All state lives in .tns/ — traceable even after a crash
Defense in depth preflight, pre_step, post_step, post_run layered validation
Crash-safe locks runner, workspace, state coordinated through named locks

Core thesis

TNS doesn't replace the agent — it places the agent inside a governable execution environment. Task boundaries, permissions, validation, recovery, audit, and handoff after usage limits no longer depend on a single conversation window staying alive.

How AVM works

From natural-language tasks to simulatable finite-state programs.

01 Source

task.md describes goals, sections, and acceptance criteria; tns_config.json describes workspace, permissions, validators, and hooks.

02 Compile

tns compile produces .tns/compiled/program.json, turning implicit workflow into an explicit FSM with external dependencies.

03 Run

The runtime picks the current section, invokes the executor, hands off to the verifier, and runs validators and policy at every stage.

04 Recover

Activity, reviews, handoff, locks, and heartbeat are all persisted. After interruption, tns recover or simply continue.

Quick start

Install the npm CLI and initialize a runnable workspace.

npm install -g token-never-sleeps

tns init --workspace ./my-task
cd ./my-task
tns compile --config ./tns_config.json
tns doctor --config ./tns_config.json
tns run --config ./tns_config.json --once
tns status --config ./tns_config.json

Operational mode

Short tasks use run --once for manual stepping; long tasks use tns start, which enters managed runner mode when tmux is configured, or direct mode otherwise. Use tns btw for read-only observation during long runs — it won't contend for the workspace lock.
