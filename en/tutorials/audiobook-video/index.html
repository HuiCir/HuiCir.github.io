Audiobook Video: From Chapter Text to Deterministic Editing

This case study demonstrates how TNS orchestrates a complete media production pipeline: converting Chinese chapter text into an English audiobook short, with manifest generation, multi-voice TTS, background image and BGM generation, deterministic ffmpeg assembly, and final QA.

3 sections 2 approval tags External tools: ffmpeg, ffprobe

Overview

The audiobook-video template is a complete real-machine case from the TNS archive. It's not a "the agent writes some text" demo — it requires the source chapter, English script, multi-voice assets, 16:9 background image, BGM, ffmpeg editing, subtitle burn-in, and final video QA to all be traceable and recoverable.

Why this case matters

It proves TNS isn't just for pure code tasks. Production pipelines involving generative assets, external CLI tools, and strict acceptance criteria can gain governability through section splitting, approval boundaries, and validators.

Task structure

The entire workflow is split into 3 sections, each with clear inputs, outputs, and acceptance criteria:

Section 1: Manifest generation

Input: a Chinese source chapter. The executor agent rewrites the content into English and produces src/production_manifest.json. The manifest includes:

  • English script (one line per subtitle)
  • Voice role assignments (which sentences use which voice profile)
  • Scene descriptions (background image prompts and BGM style hints)
  • Timestamp constraints (estimated duration per sentence, used for editing)

The manifest is the "contract" for all subsequent steps — once generated, sections 2 and 3 never need to refer back to the source text.

Validation script: node scripts/check_manifest.mjs

Section 2: Media asset generation

Based on the manifest descriptions, generate all media assets:

  • Speech files: use TTS or voice cloning to produce per-sentence speech clips for each role
  • Background image: generate a 16:9 image from the scene description
  • BGM: generate or select background music based on style hints

This section requires external network access and generation APIs, so it uses the media-assets approval tag.

Validation script: node scripts/check_manifest.mjs --assets

Section 3: Deterministic edit and QA

Assemble all assets into the final video:

  • Concatenate speech clips by timestamp using ffmpeg
  • Overlay the background image, mix multi-voice audio tracks
  • Burn in English subtitles
  • Mix in BGM
  • Output a 1080p H.264 video

Build script: node scripts/build_video.mjs

Validation script: node scripts/check_video.mjs, which verifies:

  • Resolution is 1920×1080
  • Both video and audio streams are present
  • Duration is within the expected range
  • Subtitle stream is correctly encoded

Permission & approval tag design

This is one of the most important design decisions in this case: different sections use different permission profiles.

{
  "permissions": {
    "default_profile": "standard",
    "profiles": {
      "standard": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["pwd", "ls", "cat", "sed", "rg", "find", "git", "node"],
        "workspace_only": true
      },
      "media_assets": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["node", "curl", "python3"],
        "requires_approval": "media-assets",
        "workspace_only": false
      },
      "media_render": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["node", "ffmpeg", "ffprobe"],
        "requires_approval": "media-render",
        "workspace_only": true
      }
    },
    "section_profiles": [
      { "match_title": "Media generation", "profile": "media_assets" },
      { "match_title": "Deterministic edit and QA", "profile": "media_render" }
    ]
  }
}

Design rationale:

  • standard profile — only safe local commands (ls, cat, git, node, etc.), confined to the workspace. Used for section 1 manifest generation.
  • media_assets profile — allows network requests and Python for calling external TTS/image generation APIs. Gated by the media-assets approval tag so the operator reviews before granting.
  • media_render profile — allows ffmpeg/ffprobe, but confined to the workspace to prevent system file access. Gated by media-render approval tag so media is verified before rendering.

Run flow

The operator follows this sequence in the terminal:

# Initialize workspace (using audiobook-video template)
tns init --workspace ./av-case --template audiobook-video
cd ./av-case

# Compile task and config
tns compile --config ./tns_config.json

# Run diagnostics
tns doctor --config ./tns_config.json

# First round (executes section 1: manifest)
tns run --config ./tns_config.json --once

# Before section 2, approve the media-assets tag
tns approve --config ./tns_config.json --tag media-assets --note "assets reviewed"
tns run --config ./tns_config.json --once

# Before section 3, approve the media-render tag
tns approve --config ./tns_config.json --tag media-render --note "media verified"
tns run --config ./tns_config.json --once

# Check final status
tns status --config ./tns_config.json

Recovery scenario

Suppose the process crashes during section 3's ffmpeg render (OOM, power loss, etc.):

# After reboot, enter the workspace
cd ./av-case

# Observe current state
tns status --config ./tns_config.json
# Output: section 3 state is in_progress, runtime is stale

# Clean up residual state
tns recover --config ./tns_config.json

# Recompile (ensure the contract is up to date)
tns compile --config ./tns_config.json

# Resume (section 3 retries from the beginning)
tns run --config ./tns_config.json --once

Because all intermediate assets (manifest, speech files, images, BGM) are persisted in .tns/ and the workspace, section 3 can safely retry from scratch without regenerating media assets.

Key takeaways

Section boundaries are recovery boundaries

Section 1's manifest is the input contract for section 2. If all three steps were crammed into one section, a crash would require restarting everything.

Approval tags are human decision points

Let the agent produce the manifest first. The operator reviews it before granting media generation permissions. Never give the agent full permissions from the start.

Deterministic validation beats natural-language judgment

check_video.mjs uses ffprobe for numeric checks (resolution, duration, stream count) rather than asking a verifier to "look at the video."

The file system is the state bus

Manifest, speech clips, background images, and BGM all live on the file system. The operator can inspect intermediate outputs anytime with ls and cat.

Adaptation ideas

This template can be adapted into multiple media production workflows:

  • Podcast generation: drop the video track, keep multi-voice audio + BGM.
  • Multilingual audiobooks: section 1 outputs multilingual manifests, section 2 generates speech per language.
  • Slideshow videos: replace the single background image with multiple slides, switched by manifest timestamps.
  • API-driven short videos: section 2 fetches content from a news API, section 3 auto-generates a daily summary video.

The key is preserving the section-splitting and approval-boundary design philosophy, not just tweaking a few scripts.
