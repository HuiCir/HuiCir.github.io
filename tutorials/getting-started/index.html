Getting Started with TNS

从零开始，用 10 步构建一个可运行的 TNS workspace。完成本教程后，你将理解 TNS 的核心循环： init → compile → doctor → run → status。

预计时间：15 分钟 需要 Node.js 22+ 需要 claude CLI

前提条件

开始之前，确保你的环境满足以下要求：

  1. 安装 Node.js 22 或更高版本

    TNS 是 TypeScript npm 包，需要 Node.js 运行时。

    node --version
# 应输出 v22.x.x 或更高

  2. 确认 claude CLI 在 PATH 中

    TNS 通过 claude CLI 调用 agent。运行以下命令确认可用：

    claude --version
# 应输出版本号

  3. （可选）安装 tmux

    tmux 不是必需的，但推荐用于 managed runner 模式。macOS 上 brew install tmux 即可。

Step 1：安装 TNS

npm install -g token-never-sleeps
tns help

全局安装后，tns 命令即可在终端中使用。tns help 列出所有可用子命令。

Step 2：初始化 workspace

用 tns init 创建一个新的 workspace。这个命令会生成 task.md、tns_config.json 和 .tns/ 状态目录。

tns init --workspace ./hello-tns
cd ./hello-tns
ls -la

你会看到以下文件结构：

hello-tns/
├── task.md              # 任务描述（你写）
├── tns_config.json      # workspace 配置
└── .tns/                # 运行时状态目录

Step 3：理解 task.md

task.md 是 TNS 的核心输入。它描述任务目标、section 拆分和验收标准。一个良好的 task.md 应该：

  • 目标明确：一句话说清楚要完成什么。
  • Section 可验证：每个 section 有明确的输入和验收条件。
  • 边界清晰：不要让一个 section 同时承担探索、实现和 QA。

打开 task.md，你会看到一个模板结构。按需修改目标和 section，然后保存。

Step 4：理解 tns_config.json

tns_config.json 控制 workspace 的行为。关键字段：

  • workspace — 路径、名称、模板信息。
  • permissions — 权限 profile 和 section-profile 映射。
  • monitor — watchdog heartbeat 和 agent 超时设置。
  • program — 可选的显式 FSM 程序。

首次使用时，默认配置即可满足大部分需求。后续可以通过 tns compile --synthesize 自动优化。

Step 5：编译

tns compile 将 task.md 和 tns_config.json 编译为结构化的 orchestration program：

tns compile --config ./tns_config.json

输出文件 .tns/compiled/program.json 包含了：

  • task section 和 required inputs
  • bridge files 和 state files
  • lifecycle 和 watchdog 设置
  • permission profiles 和 approval tags
  • validators 和 command hooks

编译后，executor 和 verifier 不再需要"猜测"任务结构——一切都在 contract 中明确定义。

Step 6：运行 doctor 诊断

首次运行前，建议先执行 tns doctor：

tns doctor --config ./tns_config.json

doctor 检查以下内容：

  • 配置文件语法和字段完整性
  • 必需二进制文件（node、claude、可选 tmux）
  • workspace 目录结构和权限
  • preflight 条件是否满足

如果 doctor 报告任何问题，先修复再继续。

Step 7：第一次运行

使用 --once 标志执行单步运行，观察 TNS 的完整循环：

tns run --config ./tns_config.json --once

运行时你会看到：

  1. runtime 选择当前 section
  2. executor agent 被调用，处理该 section
  3. verifier agent 检查输出，产生 review
  4. policy 根据验证结果决定状态迁移

Step 8：查看状态

运行后，用 tns status 查看 workspace 的当前状态：

tns status --config ./tns_config.json

status 报告：

  • 每个 section 的完成状态
  • 是否有 freeze 或 pending approval
  • runtime heartbeat 和 active agent 信息
  • artifacts 和 locks 状态

Step 9：监控长任务

对于需要多轮推进的任务，使用 tns btw 进行只读观察（不抢 workspace lock）：

tns btw --config ./tns_config.json --events 12 --reviews 5

使用 tns trace 查看最近的事件轨迹：

tns trace --config ./tns_config.json --limit 40

Step 10：恢复与清理

如果任务中断（进程死亡、网络失败等），使用 tns recover 清理残留状态：

tns recover --config ./tns_config.json
# 如果需要强制清理：
tns recover --config ./tns_config.json --force

恢复后可以直接继续运行——TNS 从 .tns/ 中的状态文件恢复上下文。
