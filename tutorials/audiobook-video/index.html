Audiobook Video：从章节文本到确定性剪辑

这个案例展示 TNS 如何编排一个完整的媒体生产流程：将中文章节文本转化为英文有声短片， 包含 manifest 生成、多 voice 语音合成、背景图与 BGM 生成、ffmpeg 确定性剪辑和最终 QA。

3 个 section 2 个 approval tag 外部工具：ffmpeg, ffprobe

案例概览

audiobook-video template 是 TNS archive 中的完整实机案例。它不是"agent 写点文字"式的 demo—— 它要求源章节、英文脚本、多 voice 资产、16:9 背景图、BGM、ffmpeg 剪辑、字幕烧录和最终视频 QA 全部可追踪、可恢复。

为什么这个案例重要

它证明了 TNS 不只适合纯代码任务。涉及生成式资产、外部命令行工具和严格验收标准的生产流程， 同样可以通过 section 拆分、approval boundary 和 validator 获得可治理性。

任务结构

整个流程被拆分为 3 个 section，每个 section 有明确的输入、输出和验收标准：

Section 1：Manifest 生成

输入中文源章节文本。executor agent 将内容改写为英文，并生成 src/production_manifest.json。manifest 包含：

  • 英文脚本（每句对应一条字幕）
  • voice 角色分配（哪些句子用哪个 voice profile）
  • 场景描述（背景图 prompt 和 BGM 风格提示）
  • 时间戳约束（预估每句时长，用于后续剪辑）

manifest 是后续所有步骤的"合约"——它一旦生成，section 2 和 section 3 不再需要回溯源文本。

验证脚本：node scripts/check_manifest.mjs

Section 2：媒体资产生成

基于 manifest 中的描述，生成所有媒体素材：

  • 语音文件：调用 TTS 或 voice cloning 为每个角色生成对应句子的 speech clip
  • 背景图：根据场景描述生成 16:9 背景图像
  • BGM：根据风格提示生成或选择背景音乐

本 section 需要外部网络和生成 API，因此使用了 media-assets approval tag。

验证脚本：node scripts/check_manifest.mjs --assets

Section 3：确定性剪辑与 QA

将所有素材组装为最终视频文件：

  • 使用 ffmpeg 将 speech clip 按时间戳拼接
  • 叠加背景图，合成多 voice 音轨
  • 烧录英文字幕
  • 混入 BGM
  • 输出 1080p H.264 视频

剪辑脚本：node scripts/build_video.mjs

验证脚本：node scripts/check_video.mjs，检查：

  • 分辨率是否为 1920×1080
  • 视频流和音频流是否存在
  • 时长是否在预期范围内
  • 字幕流是否正确编码

权限与 Approval Tag 设计

这是本案例最关键的设计决策之一：不同 section 使用不同的权限 profile。

{
  "permissions": {
    "default_profile": "standard",
    "profiles": {
      "standard": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["pwd", "ls", "cat", "sed", "rg", "find", "git", "node"],
        "workspace_only": true
      },
      "media_assets": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["node", "curl", "python3"],
        "requires_approval": "media-assets",
        "workspace_only": false
      },
      "media_render": {
        "permission_mode": "acceptEdits",
        "allowed_bash_commands": ["node", "ffmpeg", "ffprobe"],
        "requires_approval": "media-render",
        "workspace_only": true
      }
    },
    "section_profiles": [
      { "match_title": "Media generation", "profile": "media_assets" },
      { "match_title": "Deterministic edit and QA", "profile": "media_render" }
    ]
  }
}

设计理由：

  • standard profile — 只允许安全的本地命令（ls、cat、git、node 等），限制在 workspace 内。用于 section 1 的 manifest 生成。
  • media_assets profile — 允许网络请求和 Python，用于调用外部 TTS/图像生成 API。加上 media-assets approval tag，确保 operator 审核后再放开。
  • media_render profile — 允许 ffmpeg/ffprobe，但限制在 workspace 内，防止访问系统文件。加上 media-render approval tag，确保 media 准备好后再渲染。

运行流程

operator 在终端中按以下顺序操作：

# 初始化 workspace（使用 audiobook-video template）
tns init --workspace ./av-case --template audiobook-video
cd ./av-case

# 编译 task 和 config
tns compile --config ./tns_config.json

# 诊断检查
tns doctor --config ./tns_config.json

# 第一轮运行（执行 section 1：manifest）
tns run --config ./tns_config.json --once

# 进入 section 2 前，需要审批
tns approve --config ./tns_config.json --tag media-assets --note "assets reviewed"
tns run --config ./tns_config.json --once

# 进入 section 3 前，再次审批
tns approve --config ./tns_config.json --tag media-render --note "media verified"
tns run --config ./tns_config.json --once

# 查看最终状态
tns status --config ./tns_config.json

恢复场景

假设在 section 3 的 ffmpeg 渲染过程中进程崩溃（比如 OOM 或电量耗尽）：

# 重启后，进入 workspace
cd ./av-case

# 观察当前状态
tns status --config ./tns_config.json
# 输出：section 3 状态为 in_progress，runtime 为 stale

# 清理残留状态
tns recover --config ./tns_config.json

# 重新编译（确保 contract 最新）
tns compile --config ./tns_config.json

# 继续运行（section 3 从头重试）
tns run --config ./tns_config.json --once

因为所有中间产物（manifest、语音文件、图片、BGM）都落在 .tns/ 和 workspace 内， section 3 可以安全地从头重试，不需要重新生成 media 资产。

关键经验

Section 边界就是恢复边界

section 1 的 manifest 是 section 2 的输入契约。如果把三个步骤塞进一个 section，崩溃后必须全部重来。

Approval tag 是人工决策点

让 agent 先产出 manifest，operator 审核通过后再放开媒体生成权限。不要一开始就给 agent 全权限。

确定性验证优于自然语言判断

check_video.mjs 用 ffprobe 做数值检查（分辨率、时长、流数量），而不是让 verifier"看一下视频"。

文件系统是状态总线

manifest、speech clip、背景图、BGM 都在文件系统上。operator 可以随时用 ls 和 cat 检查中间产物。

扩展思路

这个模板可以适配为多种媒体生产流程：

  • 播客生成：去掉视频轨道，只保留多 voice 音频 + BGM。
  • 多语言有声书：section 1 输出多语言 manifest，section 2 为每种语言生成 speech。
  • slideshow 视频：将背景图替换为多张幻灯片，按 manifest 时间戳切换。
  • API 驱动的短视频：section 2 从新闻 API 拉取内容，section 3 自动生成每日摘要视频。

关键在于保持 section 拆分和 approval boundary 的设计思路，而不是改几行脚本。
