Token Never Sleeps Agent Virtual Machine

TNS AVM 是一个 deterministic、file-system-stateful 的 agent orchestration runtime。它把自然语言任务编译成 明确的机器 contract，再用外部 loop 管理 executor、verifier、权限、validator、watchdog 和恢复路径。

2026-04-28 Source: /root/TNS_AVM_TECHNICAL_REPORT.md npm v1.0.2

Abstract

TNS AVM 为长时 Claude agent workflow 提供一层可恢复、可验证、可审计的虚拟机。它定义了有限状态执行引擎、 轻量 ISA、分阶段 validator、权限 profile、resource lock、watchdog heartbeat 和文件系统状态总线。输入是 `task.md` 与 `tns_config.json`；输出是 `.tns/compiled/program.json` 以及一组运行时状态文件。

Design claim

long-horizon agent work 的核心约束不是“模型一次能想多远”，而是任务能否在 fresh context、失败、中断、权限门禁和验证环节之间继续推进。

Problem model

TNS AVM 直接面对五类长期任务风险：

  • 进程死亡、网络失败或 usage limit 后，工作需要从磁盘状态恢复。
  • 开放式 agent 容易 scope creep，必须由 runtime 固定 section 边界。
  • shell、文件和网络能力需要按 stage 控制，而不是全部放开。
  • 输出必须由 verifier、validator 和 command hooks 系统验收。
  • 调试需要可重放的 program、activity log 和状态快照。

Design principles

File system as state bus

`.tns/` 内部用 JSON、JSONL 与 Markdown 存储 manifest、sections、reviews、handoff、locks 和 activity。

Natural language to contract

`tns compile` 把 task/config 编译成 `program.json`，使 section、validator、permission 和 external tools 显式化。

Agent-as-coprocessor

agent 不控制 loop。AVM 分配一个 section，agent 返回结构化结果，runtime 决定状态迁移。

Staged validation

preflight、pre_step、post_step、post_run 均可绑定 validator 与 command set，并由 policy 决定阻断或修复。

CLI layer 提供 `init`、`compile`、`simulate`、`run`、`start`、`status`、`btw`、`approve`、`recover` 等操作； core layer 负责 workflow、sections、FSM、agent bridge、state、runtime、policy、permissions、validators 与 command bridge。

AVM ISA

AVM 的 FSM 程序包含 `task`、`decision`、`loop`、`terminal` 四类 state。每个 state 可声明 `on_enter` 指令和有条件的 transitions。ISA 保持很小，目的是让 orchestration 可读、可模拟、可审计。

OpcodeTypeSemantics
setdata向 context dotted path 写入值。
inc / decdata对数值寄存器做加减，用于 retry、budget、loop counter。
appenddata把事件或中间值追加到数组路径。
ifcontrol按 condition 执行 then/else 指令块。
whilecontrol带 max_iterations 的受限循环，避免无限自扩张。
emitside effect向 simulation trace 写入事件。

Validation and policy

AVM 将“验收”从 agent 的自我判断中拿出来。validator 可以检查文件存在、文本正则、JSON path、命令集合结果； policy 再决定失败后是 `block_section`、`mark_needs_fix`、`freeze` 还是 `fail_run`。这让失败成为可路由状态，而不是日志里的一句抱怨。

Permissions and locks

permission profile 按 section 匹配 allowed bash commands、workspace-only path audit 和 approval tag。高风险步骤会冻结 workspace， 直到 operator 使用 `tns approve --tag ...` 授权。所有 mutating flow 使用 `.tns/locks/` 的命名锁，并通过 PID 与时间戳识别 stale lock。

Recovery model

运行时持续写 heartbeat；单个 Claude follow session 超过 `monitor.max_agent_runtime_seconds` 时会被 watchdog 标记为 retryable。 `tns recover` 清理 stale runtime、locks 和 lingering in_progress sections。若所有 sections 已经 terminal，semantic recovery 可以直接释放锁。

Validated case

audiobook-video template 是 AVM 思路的实机样例：它把“英文改写与 manifest”“媒体生成”“确定性剪辑与 QA”拆成三段， 对外部工具、资产文件、ffmpeg 输出和视频检查分别建 validator 与 approval boundary。这个 case 说明 TNS 不是只适合代码任务， 也适合包含生成式资产、命令行工具和严格验收的生产流程。
